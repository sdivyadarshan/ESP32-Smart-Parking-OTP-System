# Algorithm and State Logic

## State variables

- `slotOccupied`: whether the single demo slot is occupied.
- `entryPending`: an entry OTP is awaiting verification.
- `exitPending`: an exit OTP request is awaiting verification.
- `sessionOtp`: four-digit session credential retained from entry to exit.

## Entry flow

1. Debounce the entry sensor and detect a HIGH-to-LOW transition.
2. If the slot is free and no request is pending, generate a pseudo-random four-digit OTP (1000–9999).
3. Start a two-minute request timeout.
4. Display the OTP and ESP32 local IP on the LCD.
5. User submits the OTP through the ESP32-hosted web form.
6. Correct OTP while entry is pending marks the slot occupied and opens the servo. Incorrect OTP leaves the request active for retry.
7. Entry timeout clears the pending request and OTP.

## Exit flow

1. Debounce the exit sensor and detect a HIGH-to-LOW transition.
2. Only if the slot is occupied, activate exit verification.
3. Request the same OTP used for entry.
4. Correct OTP while exit is pending releases the slot, clears the OTP and opens the servo.
5. Incorrect OTP leaves the slot occupied and allows retry.
6. Exit timeout cancels the request but does not release the slot.

## State transitions

| State | Event | Result |
|---|---|---|
| Free / idle | Entry sensor | Entry pending; OTP generated |
| Entry pending | Correct OTP | Occupied / idle; gate opens |
| Entry pending | Wrong OTP | Remain entry pending |
| Entry pending | Timeout | Free / idle; OTP cleared |
| Occupied / idle | Exit sensor | Exit pending |
| Exit pending | Correct OTP | Free / idle; OTP cleared; gate opens |
| Exit pending | Wrong OTP | Remain exit pending |
| Exit pending | Timeout | Occupied / idle |

## Gate and sensor logic

Sensor inputs use a 40 ms stable-state debounce. The gate uses a timestamp to close after two seconds without blocking the main loop, allowing HTTP requests and sensor checks to continue.

## Security limitations

The OTP is a short demonstration credential generated by the ESP32 pseudo-random generator. The local page uses plain HTTP and does not implement TLS, rate limiting, persistent sessions, brute-force protection or identity management. It is not suitable as production access-control security.
